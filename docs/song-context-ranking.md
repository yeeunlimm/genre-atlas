# 검색곡 하나 기준 ML — 실제 실험과 적용 상태

2026-10-07 로컬 실험. 이전 사용자 취향 모델과 제작진 16열 모델은 수정하거나 재사용하지 않았다.

## 사용자가 입력하는 것

검색 결과에서 선택한 곡 하나. 로그인·과거 좋아요·싫어요 기록은 ML 입력에 필요 없다.
일반 추천의 기존 `selectedSongMemory`는 과거 반응을 점수 가중치에 넣지 않는다.
이미 찜한 곡·싫어요·최근 반복 제외는 유지한다. 찜 기반 플레이리스트는 별도 기능이다.

```text
선택곡 → 제작진/샘플 후보 수집 → 선택곡과 후보의 특징 비교
       → 승인 모델이 있을 때만 제작진 80% + ML 20% → 기존 제외 조건 → 추천
```

## 실제로 학습한 자료

기존 ML 실험 폴더에 보존된 ListenBrainz 공식 2025-06-10 공개 표본을 읽기만 했다.
입력: recording_feedback, recording_artist, recording_genre, recording_length Parquet.
출처와 배포 파일 체크섬은 원본 `data/manifest.json`에 있다. 원본·개인 평가를 GitHub에 복사하지 않는다.

- 중복 평가 7,159행 제거, 상충 평가 1쌍 제거. 평가가 없는 곡은 싫어요로 만들지 않았다.
- 최소 좋아요 5개·싫어요 3개가 있는 116명을 사용자 단위로 분리했다.
- 한 사람의 실제 좋아요 중 최대 2곡을 각각 독립적인 기준곡으로 사용한다. 추천 시 한 번에 받는 기준곡은 **하나**다.
- 기준곡과 아티스트가 겹치는 후보, 아티스트 식별 정보가 없는 후보는 제외한다.
- Y는 같은 사람이 후보에 남긴 실제 좋아요=1, 싫어요=0다.
- 이는 **선택곡과 함께 선호한 곡을 찾는 대리 실험**이다. 다음 곡으로 추천했을 때 만족했다는 관측도, 실제 함께 청취한 로그도 아니다. 타임스탬프가 없어 시간순 검증이라고 부르지 않는다.

| 구간 | 사용자 | 기준곡 추천 묶음 | 비교 행 | 좋아요 / 싫어요 |
|---|---:|---:|---:|---:|
| Train | 75 | 149 | 9,368 | 7,631 / 1,737 |
| Validation | 17 | 34 | 2,080 | 1,639 / 441 |
| Test | 24 | 48 | 2,632 | 1,995 / 637 |

같은 사용자는 구간을 넘나들지 않는다. 한 사용자의 여러 묶음은 최종 평가에서 먼저 평균하여 사용자 수가 부풀려지지 않게 했다.

## X — 56개 숫자

- 8개 공통 비교: 장르 교집합/합집합, 선택곡 장르 중 겹침 비율, 후보 장르 중 겹침 비율, 짧은 길이/긴 길이, 두 곡 각각의 장르·길이 존재 여부.
- Train에 나타난 빈도 상위 장르 24개의 포함 여부를 선택곡 24열 + 후보곡 24열로 추가. Validation/Test로 장르 사전을 정하지 않는다.
- 미확인 비교는 -1로 구분한다. 곡 단위 장르만 사용하며 아티스트·앨범 장르를 곡 장르로 위장하지 않는다.
- 사용자 이력·사용자 ID·가수 이름/ID·곡 ID·제작진 점수·인기도는 모델 X가 아니다. ID는 중복/분리/검증에만 사용한다.
- 소리, BPM, 리뷰 감성, 음원 분석은 없다. 장르 표기의 정확한 겹침이지 소리 유사도 측정이 아니다.

## 학습과 실제 결과

CatBoostRanker / YetiRankPairwise, 최대 350회, 깊이 4, 학습률 0.04.
Validation 상위 10곡 순위 지표(NDCG@10)가 40회 개선되지 않으면 종료. 최종 **98개 나무**가 저장됐다.
상세 동작은 [CatBoost 공식 문서](https://catboost.ai/docs/en/concepts/python-reference_catboostranker)를 따른다.

| Test 정렬법 | NDCG@10 (높을수록 좋음; 만족 확률 아님) |
|---|---:|
| 새 CatBoost | 0.7681 |
| 단순 장르 겹침 | 0.7699 |
| Train 사용자들의 인기순 | 0.7293 |

비교할 기준선은 Validation에서 단순 장르 겹침으로 선택한 뒤 고정했다.
Test에서 ML−기준선 차이는 −0.00187, 사용자 단위 95% 재표집 구간은 [−0.04997, +0.04764]다. 개선을 확인하지 못했다.
선택곡을 무작위로 바꾼 시험과의 차이도 불확실했다. 학습에서 한 번도 본 적 없는 후보 가수만으로는 좋아요/싫어요가 함께 있는 시험 묶음이 없어 성능을 검증할 수 없었다.

**오프라인 원본은 `approved:false`로 보존했다. 2026-10-07 사용자의 명시적인 사이트 적용 요청에 따라 숫자 나무만 배포용으로 승인했다. 이는 성능 개선 승인이 아니라 실험 운영 승인이다.**
배포 파일은 `models/station-ranker.json`이며 원본 평가 행·사용자 ID·학습표를 포함하지 않는다. API는 `deploymentMode: experimental`, `qualityImprovementVerified: false`를 함께 반환한다. 곡 단위 장르가 있는 선택곡에 기존 제작진 80% + ML 20% 결합을 적용하고, 메타데이터가 없으면 기존 규칙을 유지한다. 실제 배포 성공 여부는 별도 검증한다.
이 데이터에는 실제 제작진 추천 후보와 제작진 점수가 없으므로, 80:20 결합의 서비스 성능까지 검증했다고 말할 수 없다.
실제 검색 결과는 다른 정보원·누락률을 가지므로 온라인 입력 범위 검증도 필요하다.

## 연결과 검사

`lib/song-context-features.ts`가 검색곡/후보의 X를 만든다. `lib/catboost-seed-ranker.ts`는 모델 종류별 X 계약을 구분한다.
이전 모델 파일을 이름만 바꿔 새 모델로 사용할 수 없다. 미승인·누락 모델은 기존 규칙으로 돌아간다.
곡 단위 장르가 없는 선택곡도 기존 규칙으로 돌아간다. 승인 숫자 나무만 브라우저로 전달하고 원본 학습 행은 전달하지 않는다.
숫자 나무 추론은 음악 API를 추가 호출하지 않는다. 학습 자료에 없는 곡도 같은 특징이 있으면 계산 가능하지만 정확도 보장은 아니다.

실험 결과: `work/song-context-20261007/` (Git 제외).
- `evaluation.json`: 결과·학습 곡선·특징 중요도·제한점
- `test-preview.csv`: 실제 시험 X·Y·예측 점수 (공개 업로드 금지)
- `candidate-model.json`: 미승인 숫자 나무
- `parity-fixture.json`: Python과 웹 계산을 비교하는 로컬 검사 자료

재실행은 기존 결과를 덮어쓰지 않는 새 실험 출력 경로를 지정한다. 새 사이트 복사본은 만들지 않는다.

```text
python scripts/train-song-context-ranker.py --data <원본-data-폴더> --output <새-비공개-실험-경로>
python scripts/test-song-context-training.py --data <원본-data-폴더> --run work/song-context-20261007
node scripts/test-song-context-ranker.cjs work/song-context-20261007/parity-fixture.json
```

Python에는 CatBoost·NumPy·Pandas·PyArrow가 필요하다. 필요한 경우 `--packages <설치폴더>`를 반복 지정한다.
공개 모델 배치는 데이터 사용 조건·메타데이터 범위·시험 성능 검토 후 별도 결정한다.
